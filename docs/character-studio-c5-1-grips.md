# Character Studio — C5.1 sword-grip implementation record

Scope: one procedural reference sword and single-hand gripping in Studio only. No combat renderer replacement, combat domain changes, two-hand IK, shield, bow, Save/Load or baking.

## Implementation
- `StudioWeaponGrip.ts` defines a versioned handle descriptor, capability/hand-scoped semantic socket validation, left/right source-finger FK commands and a disposable independent Three.js mesh layer.
- Blade, guard, hilt, pommel and contrasting materials are generated locally. +Y is pommel-to-tip. Physical handle dimensions are estimated from the **current posed wrist/knuckle landmarks**, with explicit safe bounds and a reduced-size visual reference for small hands. The renderer owns and disposes this geometry.
- Calibration composes `socketWorld × socketOffset`; subsequent wrist/body pose changes follow the live same skinned runtime, not a separate character or gameplay model.
- Studio's Pose area offers None/Right hand/Left hand and a hand Focus action. Equipment is presentation-only, and rebuilding morphology replaces the owned sword layer.
- The grip command overlay retains the active Studio pose and uses the already calibrated `AnatomicalFK` flexion/opposition frames.

## Validation and remaining acceptance gates
- Unit tests cover FK bounds, mirrored semantic grip lookup, socket ownership validation, repeatable attachment transforms and root/wrist motions.
- Chromium tests exercise the selectable hands and hand Focus, capturing desktop/touch screenshots when CI executes.
- **Not yet proven:** measured collision/contact residuals on **deformed source skin**, thumb-to-handle contact under all native age/body/hand macros, guard non-penetration, wrist collision clearance, production-device frame time or qualitative visual approval. The pose commands are bounded deterministic profiles, not a fitted per-digit surface-contact solver. A test or successful build must **not** be interpreted as confirmation of those visual gates.
- The sword is a reference silhouette, not production weapon artwork. Fully coordinated arm IK is deliberately deferred.

These unsatisfied gates must be closed before marking C5.1 accepted in Issue #81. Keep the legacy combat weapon/origin unchanged and do not proceed to C5.2 on the strength of compilation alone.

## Grip-axis correction after owner preview feedback

Owner observed that the sword appeared to extend directly from the hand. The old sword-local +Y axis was the wrist-to-middle-finger direction, so the blade traveled along the fingers. The correction instead derives a right-handed sword-local frame from the **posed** MakeHuman knuckle line (little finger → index finger), projected perpendicular to the wrist-to-middle-finger direction. +Y now runs through the fist, from pommel near the little finger to guard/blade near the index finger. The same handle-centered skinned-surface fit and semantic-socket attachment are retained; no Euler-only world-axis hack or root scaling is introduced. Real imported-hand left/right tests now explicitly assert a blade/finger dot product below 0.12 and blade/knuckle-line dot product above 0.95. Those orientation tests do not establish satisfactory all-finger contact; the existing contact blockers remain separately tracked.

## C5.1 technical acceptance coverage (2026-11-15)

The new `tests/character-studio-sword-contact.test.ts` uses the original CC0 OBJ, pinned skeleton, source weights and the *real* `MakeHumanBodyController` to rebuild anatomically morphed skinned humans. It calibrates FK independently per hand, equips the existing procedural sword and transforms a deduplicated (original source ID) CPU-skinned sample into the sword's actual local frame. It checks each of five fingers, the handle cylinder, the crossguard's oriented box and wrist source skin. This is not another assertion that only tests parent transforms or finite numbers.

- **Enforced geometry checks:** every digit must have weighted surface vertices near the handle, with its closest skin sample no farther than `max(10mm, 0.75 × handle radius)`; no sampled digit may penetrate more than `max(5mm, 0.85 × handle radius)`. A positive collective count of vertices must be within 3mm of the handle cylinder. Crossguard penetration is less than 3mm, wrist penetration less than 3mm, and sampled wrist clearance more than 2mm. These conservative limits catch gross detachments/clipping while retaining the visually owner-accepted reference weapon. They **are not** tight 1mm tactile-contact or continuous collision certification. Distances are in world meters and follow the actual mesh/sword matrices; source UV duplicates are not double counted.
- **Morphology coverage:** unmodified CC0 human, male/female, short/tall stature, minimum/maximum weight and muscle, both source hand-scale modifiers, native finger-length limits, infant age 0.06 and a valid mixed macro+hand extreme. Every case is exercised on independently bound left/right hands. Morphological anatomy is rebuilt using the pinned original atlas, not artificially scaled meshes. The extreme age fixture uses an adapted small reference handle; this does not validate gameplay weapon suitability for children.
- **Pose and lifecycle:** source-calibrated grip survives existing Studio preview poses, sword socket attachment is repeatable, and neutral recovery restores rest-hand state. Existing left/right orientation, wrist/root-transform, invalid-socket and grip bounds tests remain unchanged. `e2e/studio-sword-grip.spec.ts` now also verifies the equipped sword persists through a source-backed large-hands character regeneration and captures a close-up screenshot on desktop/touch when phase acceptance runs.
- **Boundaries and remaining fidelity:** sampled vertices cannot rule out a collision occurring between neighboring triangles, and no independent MakeHuman executable oracle is run. The original source hand's flexed thumb may overlap the reference cylinder even when the user-visible pose looks correct. The measured nominal right-thumb depth before these regression gates was approximately 12.57mm; the objective gate is deliberately a *gross intersection detector*, not proof of collision-free finger contacts. A dedicated per-digit contact solver and visual precision refinement can be undertaken on verified evidence without changing authoritative combat.
- **CI policy:** the existing fast Verify workflow runs all new Vitest tests. The extra Chromium close-ups remain in Playwright but must only run under the repository's manually dispatched Phase Acceptance workflow, not automatically on this slice PR.
